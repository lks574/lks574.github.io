iOS 개발을 오래 하다가 최근 React Native나 AI 쪽 작업들을 함께 다루기 시작하면서, 낯선 기술 용어들을 마주하는 일이 부쩍 늘었습니다.

JSI, Fabric 같은 렌더러 개념부터 시작해서 백엔드의 멱등성(Idempotency), 그리고 RAG나 컨텍스트 윈도우 같은 AI 용어들까지...  
대충 감으로만 알고 넘어가다 보면 나중에 설계할 때나 AI에게 프롬프트를 짤 때 헷갈리는 순간이 생기더군요. 그래서 '나만의 기술 용어집'을 하나 만들어둬야겠다고 생각했습니다.

그런데 시작하기 전에 딱 한 가지 확실한 게 있었습니다.

> **"어차피 내가 일일이 손으로 타이핑해서 정리하진 않을 거다."**

바쁜 실무 중에 옵시디언 켜서 마크다운 표 맞추고 있을 여유는 없습니다. 결국 AI 에이전트(Antigravity나 Claude 등)한테 *"이 개념 용어집에 추가해줘"*라고 시키게 될 게 뻔했습니다.

그렇다면 애초에 **"에이전트가 다루기 가장 편한 구조"**로 만들어야 했습니다.

---

## 1. 표(Table) 방식은 왜 안 될까?

보통 용어집을 만든다고 하면 `glossary.md` 파일 하나 만들고 마크다운 표를 먼저 떠올립니다:

```markdown
| 용어 | 설명 | 링크 |
| --- | --- | --- |
| RAG | 검색 증강 생성... | ... |
```

사람이 가끔 한 줄 적기엔 괜찮지만, 이걸 에이전트한테 시키면 생각보다 골치 아픈 일들이 생깁니다:

1. **포맷을 깨먹기 쉽다:**  
   파일이 수백 줄로 길어지면 에이전트가 표 중간에 행을 끼워넣다가 파이프(`|`) 위치를 어긋나게 하거나, 줄바꿈을 잘못해서 표 전체가 깨져버리는 일이 잦습니다.
2. **기존 내용 삭제 위험:**  
   에이전트가 긴 파일의 특정 부분을 수정할 때, 실수로 엉뚱한 범위를 덮어써서 기존에 적어둔 다른 용어가 통째로 날아가는 경우가 있습니다.
3. **토큰 낭비:**  
   단어 하나 추가하려고 수백 줄짜리 문서를 매번 처음부터 끝까지 다 읽어야 하니 토큰도 아깝고 속도도 느립니다.

---

## 2. 해결책: 1단어 1파일 + 자동 집계

그래서 구조를 완전히 단순하게 바꿨습니다.

```
src/content/10-wiki/glossary/
├── ai/              # rag.md, context-window.md ...
├── architecture/    # idempotency.md, concurrency.md ...
├── client/          # jsi.md, fabric.md ...
└── product/         # feature-flag.md, lead-time.md ...
```

원리는 간단합니다:

* **에이전트는 파일 하나만 새로 만든다:**  
  새 용어가 생기면 해당 폴더에 마크다운 파일 하나만 딱 생성(`write_to_file`)하고 끝냅니다. 기존 파일은 전혀 건드리지 않으니, 실수로 다른 내용을 날려먹을 일이 원천적으로 없습니다.
* **목차 관리는 Astro에게 맡긴다:**  
  "용어 추가하고 목차 파일(`index.md`)에도 한 줄 적어줘"라고 시키면 에이전트가 잊어먹기 십상입니다. 그래서 목차 파일 자체를 없앴습니다.  
  대신 웹사이트(`/wiki/glossary/`)가 빌드될 때 폴더 안의 파일들을 긁어모아 카테고리별 탭과 검색창을 알아서 만들어주도록 했습니다.

---

## 3. 에이전트에게 룰 정해주기 (`AGENTS.md`)

에이전트가 매번 제멋대로 쓰지 않도록, 저장소 루트의 `AGENTS.md`에 가이드라인을 몇 줄 적어두었습니다:

* **저장 위치:** `glossary/{category}/{term-slug}.md`
* **중복 확인:** 만들기 전에 이미 있는 단어인지 먼저 검색할 것
* **본문 필수 항목:**
  - 💡 핵심 정의 (비유나 1줄 요약)
  - 🎯 왜 알아야 하는가? (실무 가치)
  - ⚙️ 동작 원리 & 메커니즘
  - 🔗 연관 개념
* **주의:** 목차 파일은 웹에서 자동 생성되니 건드리지 말 것

이렇게 박아두니, 이제 대화창에 이렇게만 말해도 알아서 딱 만들어줍니다:

> **나:** "용어집에 Vector DB랑 Embedding 추가해줘."  
> **에이전트:** (규칙 확인 ➡️ 중복 체크 ➡️ 파일 2개 생성 완료 ➡️ 끝)

---

## 4. 써보면서 느낀 장점

구조를 이렇게 잡고 나니 몇 가지 편한 점들이 있었습니다:

1. **스트레스가 없다:**  
   문서 서식이나 목차 순서 같은 걸 고민할 필요 없이, 그냥 떠오를 때마다 에이전트한테 던져두면 알아서 쌓입니다.
2. **나중에 질문할 때 써먹기 좋다:**  
   나중에 에이전트랑 코딩하다가 "React Native 렌더링 이슈가 있는데..." 할 때, 에이전트가 용어집의 `client/fabric.md` 파일만 쏙 가져다가 읽고 맥락을 잡을 수 있습니다. 거대한 단일 문서보다 작은 단위 파일이 AI에게 먹여주기 훨씬 편하더군요.
3. **검색이 빠르다:**  
   Astro 페이지에 간단한 자바스크립트 검색을 붙여뒀더니, 영문 약어나 한글 이름으로 바로바로 찾아보기 편합니다.

---

## 마무리

거창한 시스템을 만들 생각은 아니었습니다. 그저 **"내가 직접 안 쓸 거라면, 일 시킬 상대(에이전트)가 실수 안 하고 가장 일하기 편한 방식으로 판을 깔아주자"**는 생각으로 정리해 본 결과물입니다.

AI를 도구로 쓸 때 가장 중요한 건, 어쩌면 프롬프트를 화려하게 쓰는 것보다 **에이전트가 일하기 쉬운 파일 구조와 규칙을 만들어주는 것**일지도 모르겠습니다.
