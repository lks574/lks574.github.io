# 용어 추가 절차

규칙의 원문은 저장소 루트 `AGENTS.md`의 "Glossary Protocol"이다. 이 스킬은 그 규칙을 실행 순서로 옮긴 것이다.
모든 명령은 저장소 루트에서 실행한다.

## 0. 입력 정리
- 용어 영문명, 한글명, 카테고리 후보(ai | architecture | client | product)를 정한다.
- 카테고리가 애매하면 "이 용어를 실무에서 누가 먼저 검색할까"로 판단한다. 예: JSI는 RN 개발자 → client.

## 1. 중복 검사 (건너뛰기 금지)
```bash
npm run glossary:find -- "<영문명>"
npm run glossary:find -- "<한글명 또는 약어>"
```
- 출력 마지막 줄 `RESULT=`를 읽는다. `MATCH`면 새 파일을 만들지 않고 기존 파일을 읽어 부족한 섹션만 보강한 뒤 6단계로 간다.
- `MAYBE`면 실제로 같은 개념인지 판단하고, 다르면 진행한다. 같으면 기존 파일에 alias를 추가한다. `NONE`이면 진행한다.

## 2. 오늘 날짜 확보
```bash
date +%F
```
이 값을 `updatedDate`에 그대로 쓴다. 기억이나 추측으로 날짜를 적지 않는다.

## 3. 연관 개념 확인
```bash
ls src/content/10-wiki/glossary/*/
```
- 🔗 연관 개념에 넣을 링크는 이 목록에 실제로 존재하는 slug만, 그리고 **정말 함께 이해해야 하는 개념만** 넣는다. 연관 용어가 없으면 비워 둔다. 고아 경고를 피하려는 억지 링크는 금지.
- 일반 위키 노트를 링크할 때는 전체 경로를 쓴다. 예: `[[tools/react-native/architecture|RN 신 아키텍처]]`
- 이 용어가 어떤 트러블슈팅 노트나 결정 기록에서 나왔다면 `sources`에 그 노트 이름(또는 URL)을 넣는다.

## 4. 파일 생성
경로: `src/content/10-wiki/glossary/{category}/{slug}.md` (slug는 소문자 케밥 케이스, 폴더와 `category` 일치)

템플릿:
```markdown
---
title: "English Name (한글명)"
description: "1~2문장 핵심 정의"
category: "ai"
tags: ["tag1", "tag2"]
aliases: ["약어", "대체표기"]
updatedDate: YYYY-MM-DD
sources: []
---

## 💡 핵심 정의
**"10초 비유 한 줄"**

두세 문장 요약.

## 🎯 왜 알아야 하는가? (실무 가치)
* **포인트 1:** ...
* **포인트 2:** ...

## ⚙️ 동작 원리 & 메커니즘
1. **단계/구성요소 1:** ...
2. **단계/구성요소 2:** ...

## 🧭 내 실무 판단 & 사례
- 실제 적용 맥락, 제약, 결정 이유. 관련 트러블슈팅/결정 노트 [[...]] 링크와 frontmatter `sources` 등록.
- 사용자의 경험을 모르면 **지어내지 말고 사용자에게 한 문장으로 묻는다**: "이 용어를 실무에서 어디에 적용했고 무엇을 선택했나요?" 답을 받기 전까지는 이 섹션을 생략한다.

## 🔗 연관 개념
- [[slug-a]] · [[slug-b]]
```

## 5. 역링크 추가
🔗 연관 개념에 적은 각 용어집 파일을 열어, `## 🔗 연관 개념` 아래 링크 줄 끝에 ` · [[new-slug]]`를 덧붙인다.
그 파일의 다른 부분과 `updatedDate`는 건드리지 않는다. 일반 위키 노트에는 역링크를 추가하지 않는다. 린트가 단방향 링크를 error로 잡는다.

## 6. 검증
```bash
npm run lint:glossary
```
error가 0이 될 때까지 고친다. `orphan` warning은 정말 연관된 용어가 없으면 그대로 둔다. 마지막 줄의 🧭/sources 비율을 사용자에게 보고한다.

## 6b. 트러블슈팅 노트에서 출발한 경우
먼저 `npm run glossary:promote`로 승격 대기 목록을 확인한다. 출력의 `다음 행동` 열이 이 단계에서 할 일이다.
사용자가 트러블슈팅 노트를 가리키며 용어를 요청했다면, 그 노트의 `🧭 얻은 원칙` 내용을 새 용어의 `## 🧭 내 실무 판단 & 사례`에 옮기고 `sources`에 노트 경로(예: `tools/react-native/troubleshooting/metro-cache-reset`)를 넣는다. 노트 쪽 관련 용어 줄에도 `[[new-slug]]`를 추가한다.

## 7. 하지 않는 일
- `index-moc.md` 등 목차 파일에 용어 링크 추가
- 기존 용어 파일의 본문 재작성 (섹션 단위 보강만 허용)
- 존재하지 않는 용어로의 `[[링크]]`
- `index`, `../index` 같은 상대 링크
