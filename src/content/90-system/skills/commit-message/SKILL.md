# Commit Message 스킬

Conventional Commits 규격에 따라 커밋 메세지를 작성하거나 기존 메세지를 검토·수정합니다.

## 기본 포맷

**커밋 메세지는 제목 한 줄이 기본입니다.** 본문은 예외적으로만 허용됩니다(아래 작성 규칙 참조).

```
<type>: <제목>
```

scope(`(ClassName)`)는 사용하지 않습니다. 관련 클래스나 모듈이 있다면 제목 안에 자연스럽게 녹여 씁니다.

**올바른 예:**
```
feat: LoginViewModel에 로그인 및 만료 token 자동 갱신 로직 추가
fix: ProfileViewController에서 사진 업로드 후 화면이 갱신되지 않는 문제 수정
```

**사용하지 않는 예:**
```
feat(LoginViewModel): 로그인 및 만료 token 자동 갱신 로직 추가  ← scope 괄호 사용 금지
```

## Type 목록

| Type | 용도 |
|------|------|
| `feat` | 새로운 기능 추가 |
| `fix` | 버그 수정 |
| `refactor` | 기능 변경 없는 코드 리팩토링 |
| `style` | 코드 포맷팅, 세미콜론 누락 등 로직 변경 없는 형식 수정 |
| `test` | 테스트 코드 추가 또는 수정 |
| `docs` | 문서 수정 |
| `chore` | 빌드 설정, 패키지 매니저 설정 등 프로덕션 코드와 무관한 변경 |
| `perf` | 성능 개선 |
| `ci` | CI 설정 변경 |
| `revert` | 이전 커밋 되돌리기 |

## 언어 규칙

커밋 메세지는 **한글 베이스**로 작성하되, 아래 항목은 영어를 그대로 사용합니다.

**영어 유지 대상:**
- 클래스명, 함수명, 파일명, 변수명
- 피쳐 이름, 모듈 이름
- 라이브러리명, 프레임워크명
- API 엔드포인트, HTTP 메서드
- 기술 용어 (예: `ViewModel`, `DTO`, `JWT`, `WebSocket`)

**한글 사용 대상:**
- 동작 서술 ("추가", "수정", "제거", "개선" 등)
- 이유나 배경 설명
- 위 영어 대상에 해당하지 않는 모든 설명

**예시:**
```
feat: UserProfile에 닉네임 수정 기능 추가
```

```
fix: LoginViewModel에서 accessToken 만료 시 자동 갱신 로직 추가
```

## QA 티켓 수정 규칙

QA 과정에서 발견된 버그나 이슈를 수정한 커밋은 반드시 티켓 번호를 명시해야 합니다.

**포맷:**
```
fix: [티켓번호] <수정 내용>
```

**예시:**
```
fix: [QA-123] 로그인 후 홈 화면으로 이동하지 않는 문제 수정
```

```
fix: [QA-201, QA-202] 다크모드에서 텍스트 색상이 반전되지 않는 문제 수정
```

- 반드시 `fix:` 타입 사용
- 제목 맨 앞에 `[티켓번호]` 형식으로 티켓 번호 삽입 (뒤가 아닌 앞에)
- 여러 티켓이면 쉼표로 구분: `[QA-123, QA-124]`
- scope는 생략하거나 관련 모듈명 사용

사용자가 QA 관련 수정인지 명확하지 않으면, 커밋 메세지를 작성하기 전에 확인하세요.

## 작성 규칙

1. **제목**: 50자 이내, 마침표 없음
2. **본문**: **기본은 작성하지 않는다 — 커밋 메세지는 제목 한 줄.** diff 를 봐도 알 수 없는 이유·배경이 꼭 필요한 경우에만 예외적으로 1~3줄 작성(72자 줄바꿈).
   - **금지**: 변경 내역을 bullet 로 나열하는 changelog 식 본문 (diff 재나열)
   - **금지**: 미결 사항(Open Q)·후속 작업 메모 — 커밋이 아니라 Jira 티켓/태스크 문서에 기록한다
   - 여러 변경을 나열하고 싶어지면 본문을 쓸 게 아니라 커밋을 쪼갠다
3. **footer**: breaking change(`BREAKING CHANGE:`) 또는 이슈 참조 시 사용
4. **AI 서명 절대 금지**: 본문이나 footer에 AI 관련 서명을 **어떤 형태로든** 절대 포함하지 마세요. 커밋은 오로지 사람의 작업으로 남겨야 합니다.

   **금지 예시 (모두 포함 금지)**:
   ```
   Co-Authored-By: Claude Opus 4.7 (1M context) <noreply@anthropic.com>
   Co-Authored-By: Claude <noreply@anthropic.com>
   Co-Authored-By: Anthropic <...>
   🤖 Generated with [Claude Code](https://claude.com/claude-code)
   🤖 Generated with Claude
   Generated by Claude
   ```

   **적용 대상**:
   - `git commit -m` 의 heredoc 마지막 줄
   - `git commit --trailer "Co-Authored-By=..."` 옵션
   - `gh pr create --body` 의 본문 말미
   - 그 외 어떤 git 커밋·PR 관련 메세지에서도 일체 추가 금지

   사용자가 명시적으로 "서명 추가해"라고 요청한 경우에만 예외적으로 포함 가능합니다. 기본 동작은 **서명 없음**입니다.

## 작업 흐름

### 커밋 메세지 작성 (변경사항 기반)

현재 staged 변경사항:
!`git diff --cached 2>/dev/null || echo "(staged 변경사항 없음)"`

현재 unstaged 변경사항:
!`git diff 2>/dev/null || echo "(unstaged 변경사항 없음)"`

1. 위 변경사항을 바탕으로 변경의 목적과 범위 이해 (`git diff --cached`가 비어있으면 `git diff` 기준으로 판단)
2. 변경의 목적과 범위 이해
3. 적절한 type 결정 (scope 괄호는 사용하지 않음)
4. 위 규칙에 맞는 커밋 메세지 작성
5. QA 티켓 관련 수정인지 불명확하면 사용자에게 확인

### 커밋 메세지 검토

1. 사용자가 제시한 메세지를 위 규칙과 대조
2. 규칙 위반이 있으면 수정 버전 제안
3. 어떤 규칙을 왜 고쳤는지 간략히 설명
4. 규칙에 문제없으면 짧게 확인해주고 마무리
