## 1. 문제 (Problem)
위키 노트를 읽는 사람은 그 노트가 어디로 이어지는지(나가는 링크)는 본문에서 알 수 있지만, **어떤 노트가 이 노트를 참조하는지(들어오는 링크)는 알 수 없다.** 용어 하나를 읽고 나서 "이 개념을 실제로 쓴 설계 기록이나 트러블슈팅이 있는가"를 확인하려면 검색을 해야 하고, 설계 기록에서 승격된 원칙이 어느 용어에 반영됐는지도 노트 안에서는 보이지 않는다. 현재 위키 25개 노트 사이에 링크가 72개 있지만 그 방향은 한쪽만 표시된다.

## 2. 대상 사용자 (Users)
| 사용자 유형 | 상황 | 지금의 우회 방법 |
|---|---|---|
| 위키 소유자 (사용자 본인) | 용어나 개념을 다시 읽으며 관련 실무 기록을 찾을 때 | 옵시디언 그래프 뷰나 전체 검색으로 확인 |
| AI 에이전트 | 막힐 때 용어집을 참조하고 관련 사례로 이동할 때 | `grep`으로 `[[slug]]` 역검색 |
| 외부 독자 | 공개 사이트에서 개념 노트를 읽을 때 | 방법 없음. 나가는 링크만 따라감 |

## 3. 목표 (Goals)
| # | 목표 | 지표 | 기준선 | 목표치 | 측정 시점 |
|---|---|---|---|---|---|
| G1 | 들어오는 링크가 있는 모든 노트에서 참조하는 노트 목록이 보인다 | 역링크 섹션이 렌더링된 노트 수 / 들어오는 링크가 있는 노트 수 | 0 / 25 | 25 / 25 | 빌드 결과물 검사 |
| G2 | 역링크 목록은 사람이 관리하지 않는다 | 수동 편집이 필요한 파일 수 | 해당 없음 | 0 | 코드 리뷰 |
| G3 | 빌드 시간이 체감되게 늘지 않는다 | `astro build` 전체 시간 | 약 0.6초 (61페이지) | 1.0초 이하 | 빌드 로그 |

## 4. 비목표 (Non-Goals)
- 옵시디언 볼트 안의 표시. 옵시디언은 자체 백링크 패널이 있다. 이 기능은 공개 사이트 렌더링만 다룬다.
- 링크 그래프 시각화(그래프 뷰). 목록으로 충분하다.
- 링크 주변 문맥(어느 문장에서 참조했는지) 표시. 첫 버전은 노트 제목 목록만 보인다.
- 블로그 글에서 위키로 향하는 링크의 역링크 표시. 블로그는 컬렉션이 다르고 독자 흐름도 다르다.

## 5. 범위 (Scope)
### 5.1 포함
- 위키 노트와 용어 페이지 하단에 "이 노트를 참조하는 노트" 목록을 표시한다. → AC-BL-001, AC-BL-002
- 목록의 각 항목은 참조하는 노트의 제목과 링크다. 용어집 항목은 카테고리 표시를 함께 보인다. → AC-BL-003
- 들어오는 링크가 없는 노트에는 섹션을 표시하지 않는다. → AC-BL-004
- 같은 노트가 여러 번 참조해도 목록에는 한 번만 나온다. 자기 자신은 제외한다. → AC-BL-005
- 별칭 경로(`/wiki/rag`)와 정식 경로(`/wiki/glossary/ai/rag`) 어느 쪽으로 링크했든 같은 노트로 집계한다. → AC-BL-006
- 코드 블록이나 인라인 코드 안의 `[[예시]]`는 링크로 집계하지 않는다. → AC-BL-007
- 노트를 추가하거나 링크를 바꾸면 다음 빌드에서 목록이 자동 갱신된다. → AC-BL-008

### 5.2 제외
- 링크 문맥 표시, 그래프 시각화, 블로그 역링크는 다음 단계로 미룬다.
- 예외 흐름(AC-BL-004~009)의 자동화된 빌드 픽스처 테스트. 첫 버전은 수동 픽스처로 검증한다.

## 6. 사용자 흐름 (User Flow)
1. 독자가 `/wiki/glossary/architecture/idempotency/`를 연다.
2. 본문과 출처 섹션 아래에 "이 노트를 참조하는 노트" 섹션이 보인다. 항목 예: concurrency-vs-parallelism(용어집 · 아키텍처), 대용량 영상 백그라운드 업로드 설계 결정(설계 기록).
3. 항목을 누르면 해당 노트로 이동한다. 그 노트 하단에도 같은 형식의 섹션이 있어 그래프를 양방향으로 오갈 수 있다.
