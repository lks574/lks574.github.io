## 1. 문제 (Problem)
트러블슈팅 노트와 설계 기록에는 "🧭 얻은 원칙" 섹션이 있어 일화적 기억에서 원칙을 뽑아 두지만, **그 원칙이 용어집의 🧭 섹션과 `sources`에 실제로 반영됐는지는 아무도 확인하지 않는다.** 반영은 작성자가 기억하고 있을 때만 일어난다. 현재 원칙 섹션이 있는 노트 3개 중 2개는 용어 5개에 반영됐고, 트러블슈팅 노트 1개는 "아직 용어집에 없음. 후보는 …"이라고 적힌 채 남아 있다. 이 상태를 알려 주는 것이 없어서 승격 루프가 사람 기억에 의존한다.

## 2. 대상 사용자 (Users)
| 사용자 유형 | 상황 | 지금의 우회 방법 |
|---|---|---|
| 위키 소유자 | 트러블슈팅을 쓰고 나서 며칠 뒤 용어집을 볼 때 | 기억, 또는 `grep sources` |
| AI 에이전트 (add-glossary-term 스킬 실행 시) | 어떤 노트가 어떤 용어의 출처가 되어야 하는지 찾을 때 | 노트 전체를 읽고 판단 |
| 주기 점검 (블라인드 재평가, 주간 정리) | 승격 루프가 실제로 돌았는지 측정할 때 | 없음. 이번 평가에서 평가자가 손으로 셌다 |

## 3. 목표 (Goals)
| # | 목표 | 지표 | 기준선 | 목표치 | 측정 시점 |
|---|---|---|---|---|---|
| G1 | 반영되지 않은 원칙을 한 명령으로 본다 | `npm run glossary:promote` 출력에 미반영 노트가 전부 나열됨 | 명령 없음 | 누락 0건 (수동 대조와 일치) | 실행 결과 대조 |
| G2 | 린트 실행마다 승격 대기 건수가 보인다 | 린트 마지막 줄에 후보 수 표시 | 표시 없음 | 매 실행 표시 | 린트 출력 |
| G3 | 에이전트가 후보를 기계적으로 읽을 수 있다 | `--json` 출력이 유효한 JSON | 없음 | 있음 | `node -e JSON.parse` |

## 4. 비목표 (Non-Goals)
- 용어집 파일을 자동으로 고치는 것. 🧭 내용은 사용자의 실제 판단이어야 하므로 이 기능은 **보고만** 한다.
- 원칙 문장의 품질 판단. 섹션이 있는지와 연결이 있는지만 본다.
- 트러블슈팅 노트를 자동 생성하는 것.

## 5. 범위 (Scope)
### 5.1 포함
- `tools/` 아래 노트 중 🧭 섹션이 있는 노트를 일화 노트로 인식한다. → AC-PR-001
- 일화 노트의 🧭 섹션이 링크한 용어마다, 그 용어의 `sources`에 노트가 있는지와 🧭 섹션이 있는지 검사한다. 없으면 후보로 보고한다. → AC-PR-002, AC-PR-003
- 🧭 섹션에 "아직 용어집에 없음" 표기와 백틱 slug 후보가 있으면 신규 용어 후보로 보고한다. → AC-PR-004
- 용어 쪽 역검사: `sources`에 적힌 노트가 실제로 그 용어를 링크하지 않으면 보고한다. → AC-PR-005
- 사람용 표 출력과 `--json` 출력을 제공한다. 종료 코드는 항상 0 (보고서다). → AC-PR-006, AC-PR-007
- 린트 마지막 줄에 후보 총수를 표시한다. 후보는 error가 아니다. → AC-PR-008
- 픽스처 테스트로 각 후보 유형이 잡히는지 검증한다. → AC-PR-009

### 5.2 제외
- 자동 수정, 품질 판단, 옵시디언 플러그인 연동.

## 6. 사용자 흐름 (User Flow)
1. 트러블슈팅 노트를 쓰고 🧭 섹션에 `[[idempotency]]`를 링크한다.
2. `npm run lint:glossary` 마지막 줄에 "승격 대기 1건"이 보인다.
3. `npm run glossary:promote`로 어느 노트가 어느 용어에 무엇을 빠뜨렸는지 표로 본다.
4. `add-glossary-term` 스킬(6b 단계)로 용어의 🧭와 `sources`를 채우면 다음 실행에서 0건이 된다.

## 7. 리스크와 의존성 (Risks & Dependencies)

| 후보를 error로 만들면 승격 전까지 빌드가 막힌다 | 작성 흐름 방해 | 보고서와 요약 줄만. error 아님 |
